# Important point
In a C program , when we run our compiled code yaani runtime par kya hota hai ki , sabse pehle OS RAM me code ki pura machine code load karta hai and Global code and Function dono ka execution do alag types se hota hai :

1. Global Code Execution
Jitne bhi global variables hote hai , Jaise hi hum code load karte hai RAM me waise hi RAM me global variables ke liye kuch memory reserve ho jaati hai(compile time par hi decide ho jaata hai memory layout kaisa banega RAM me when we load this script file into RAM, based on the variables used in that program like int a = 5 means compile time par ek instruction add ho jaayegi machine code me ki RAM me 4bytes ki memory reserve kar lena for variable a ) , yaani RAM me global variables ke liye memory layout ban jaayega but abhi tak un reserved memory blocks me koi value nahi gayi hai . Now , ab kya hota hai ki CPU me jaise hi ek line of global code jaata hai toh wo sabse pehle store hota hai MU yaani CPU ki Memory Unit me and then uske baad wo jaata hai CU yaani Control Unit ke paas , control unit ka kaam hota hai us line of code ko samajhna , toh wo us global line of code ko understand karta hai and agar toh wo operation function call yaa variable declaration kar raha hai toh yeh kaam toh CU khud hi kar deta hai yaani like variable ko declare kar dega yaani jo space us global variable ke liye reserve hui thi starting me RAM me usme CU value daalne kaa kaam kar deta hai yaa agar koi function call hai toh wo bhi CU hi kar deta hai, But agar operation logical hai yaani us instruction yaa line of code me koi operator + , - , * etc.. use ho raha hai toh CU us kaam ko AU yaani Arithmetic Unit ko de deta hai and then AU us operation yaa us calculation ko karke , agar result ko kahi emmory me daalna hai toh daal deta hai nahi toh bus result return kar deta hai . This is how Global code yaa Global instruction ka execution hota hai 
Cleanup - Toh global variable throughout the program execution RAM me memory liye rehta hai yaani from the start of the code script like from that #include to return 0; of main() function yeh memory liye rehta hai and when the whole program execution finishes up then its memory gets released means erased from the RAM and it is because yeh ek global variable hai kahi bhi access kiya jaa sakta hai , toh throughout the code hume ise rakhna padta hai , hum ise beech me delete nahi kar sakte hai .


2. Function Code Execution
But when a function runs toh kya hota hai ki sabse pehle jab wo function call hoga toh sabse pehle real time me kuch memory area reserve hogi stack me for that function (ab kitna hoga that is calculated on compile time based on the variables present me that function) and then uske baad uske andar ka code run hoga and Using CU ek-ek karke jo reseved area tha function call hone par wo fill hota jaayega yaani value allocate hoti jaayegi, kyuki usi me us function ke local variables ki value jaati hai and agar koi line of code in that function calculation waala hai toh wo AU ke paas jaata hai and AU calculate and execute karta hai us line ko . Yaani isme code script RAM me load karte hi RAM me memory reserve nahi hoti hai like global variables do , isme real time me when function call happen then memory reserve hoti haia and then real time me when code runs line by line toh value allocation in that reserved memory and logical operations hote hai .

🟦 Recursion
🟡 Recusion is a process in which "function calls itself" and the function who does recursion called as recursive function.Matlab recursion hota hai kisi function ke andar usi function ko call kar dena . Recursion 100% same work karta hai loop ki tarah yaani alag-alag values ke saath kisi pocket of code ko repeat karta rehta hai . Recursive code is generally shorter and easier to write than iterative(loop) code . Every problem that can be solved through loop can be solved through recursion and vice versa too . Hum mostly prefer karte hai to use recursion instead of using loops to solve problems, kyuki solution to some or most problems are easier to formulate recursively than loops .
